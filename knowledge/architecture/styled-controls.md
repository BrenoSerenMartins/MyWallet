# Shared calendars and selectors

All month/date inputs and selects use shared controls in `app/src/shared/ui/controls`. They replace browser-owned popups, whose platform styling and locale cannot be controlled by CSS. Existing form values and API payloads remain ISO dates and months. The controls add no dependencies; their nonmodal portals use the existing Radix Dialog layer so that they can be opened inside financial dialogs.

Month selection shows full Portuguese names and an editable year, keyboard arrows and year navigation. Dates allow Brazilian text entry or calendar selection, with nested month selection. Incomplete/impossible typed dates set constraint validity on the hidden native bridge: submitting cannot silently reuse the last valid date. Bounds, required/disabled states and native form values remain supported. A visible invalid field receives focus; no native validation bubble is needed. Selects provide an accessible combobox/listbox, option groups, disabled options, arrow navigation and accent-insensitive typeahead. Escape closes the current popup, and selection restores the initiating field without taking focus from an outside control.

Popup positions are clamped to the visual viewport, including small screens and the onscreen keyboard. They use readable surface colors and selective backdrop blur where supported, with opaque fallback. The app's global screen-reader-only utility keeps labels, announcements and table headers accessible without displaying them in the layout. The existing action disclosure allows nested control popups without closing itself.

Planning owns its spacing with a grid gap, independently of optional notices. Budget sections and their rows sit on the canvas with separators; the financial summary retains a restrained frosted surface. The ledger remains unframed. App entry fades once per browser tab, without blocking data loading; reduced-motion preferences disable this and popup animation.

Unit tests cover date parsing, invalid dates, leap years and calendar padding at year boundaries. Browser regressions exercise desktop/mobile month controls and spacing, keyboard selection inside action menus, nested calendars, ISO filters, invalid-date submission and reduced motion. Browser discovery is not an execution pass: the current restricted environment cannot start the local browser server. No database migration is required.
