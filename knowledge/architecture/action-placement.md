# Action placement

An action has one primary home inside the active workspace. Page headers hold creation actions; empty states explain what to add without repeating the same creation button. Empty-state recovery actions that solve a different problem, and links attached to a particular account, transaction or month, remain contextual.

| Action | Primary home |
| --- | --- |
| Light, dark and system appearance | Preferences → Appearance |
| Sign out inside a workspace | Preferences → Account |
| Switch, create, archive and restore spaces | Space menu → Switch space |
| Manage category groups and categories | Space menu → Groups and categories |
| Import statements | Space menu → Import statement |
| Create an account, card, group, commitment or investment | Corresponding page header |

The space menu is a navigation layer, rather than a second settings form. Its profile footer identifies the signed-in user without repeating account controls. The portfolio destination remains available from the mobile menu but is hidden there when the desktop header already exposes it. Account/card tabs and links such as a transaction's source, balance history, or a month's plan remain contextual navigation.

Appearance controls remain on sign-in and on workspace selection when there is no active workspace, since Preferences is unavailable then. Workspace selection also retains sign-out independently of the active-workspace shell. An invitation to import in a movement empty state remains useful recovery guidance rather than a permanent overview toolbar action.

Browser coverage follows the Preferences route when changing themes, checks that workspace menus have no duplicate theme/sign-out controls, and verifies desktop/mobile portfolio access. Browser discovery does not imply visual execution in the restricted environment. No database changes are required.
